Outcomes

Response drift

Quarter learns the shape of each provider route's successful responses and raises a lead when a field is removed, retyped or added.

A provider can change a response without changing its API version: a field disappears, or a number becomes a string. Code that reads the response breaks, often quietly. Quarter compares the shape of each successful response with the shape it learned for that route, and raises a drift lead when they differ.

A drift lead is a label, never evidence. It points at code worth checking. It does not change any action, and it never makes a call retry-safe.

Where shapes come from

SDK capture records the shape of a successful JSON response: its key paths and value types, never its values. The shape is computed in your process and the body is discarded there. Calls without a shape, including calls imported through OTLP, are never checked for drift.

How a lead is raised

  • Quarter keeps one baseline shape per project and route, where a route is the host, the method and the path, such as POST api.stripe.com/v1/refunds.
  • Only responses with a 2xx status count. An error body is a different document.
  • A new baseline has to be seen a number of times before it is trusted. Until then, a different shape replaces it instead of raising a lead.
  • Once the baseline is trusted, a different shape raises a lead. The same new shape seen again adds to that lead's occurrences instead of opening another one.
KindWhenWhat to do
breakingA field was removed, or its type changed.Check the code that reads this response before the change reaches it.
informationalFields were only added.Usually nothing. Resolve it when you have looked.

diff lists each change with its path, such as data[].amount, and the type before and after. Only the outermost change is reported, so a removed object is one entry, not one per field inside it.

List leads

Filters: state (open by default, resolved or all), provider (a provider name such as stripe, or a host), kind, limit and cursor. See the API reference.

Resolve a lead

Resolving accepts the shape the lead saw as the route's new baseline, so the same change is not raised again. Resolve a lead once the code that reads the response handles the new shape. It needs the developer role and is recorded in the audit log.

The console's Drift page lists open and resolved leads and resolves them. Coding assistants read open leads with the quarter_drift MCP tool. See AI coding tools.
