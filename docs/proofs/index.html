Outcomes

Signed proofs

Fetch an action's Outcome Proof signed by Quarter, verify it offline, and keep it as a receipt that survives key rotation.

Every settled action carries an Outcome Proof: the evidence that decided its state, the ActionSpec version and plan hash it was judged against, and the time it was verified. The signed form wraps that proof in an Ed25519 signature so a customer, an auditor, or your own code can check it without trusting the API that served it.

Fetch a signed proof

body is the Outcome Proof plus tenantId, projectId, actionType and fingerprint, so a proof cannot be moved to another action or payload. An action with no proof yet returns RESOURCE_NOT_FOUND (404) with its current state in the message.

Verify offline

Fetch Quarter's public keys once from GET /v1/proof_keys and cache them. Verification then needs no network. Quarter.proofs.verify (also exported as verifyProof) returns false for a bad signature, a changed body, or an unknown keyId. It uses Web Crypto Ed25519, so it runs on Node 22, modern browsers and edge runtimes.

Verify without the SDK

  1. Find the key in /v1/proof_keys whose keyId matches the proof's keyId.
  2. Serialize { "body": proof.body, "keyId": proof.keyId } as RFC 8785 canonical JSON: keys sorted, no whitespace, undefined fields dropped.
  3. Decode signature from base64url and verify it over those UTF-8 bytes with the Ed25519 public key in publicKeyPem (SPKI).

Who approved it

When a policy such as review_above held the action and a person approved it before dispatch, the proof body carries approvedBy: the actor of the credential that called approve, followed by the request id. The field is absent when no approval took place. Because it is inside the signed body, it cannot be added or removed after the fact.

Key rotation

Proofs are signed with the same Ed25519 key that signs plans for the customer-side executor. On rotation, the new key is published before Quarter signs with it, and the old key stays in /v1/proof_keys while it is being retired. Every proof names its keyId, so proofs signed before a rotation keep verifying against the old key.

  • When you see a keyId you have not cached, fetch /v1/proof_keys again before you call a proof invalid.
  • A retired key is eventually removed from /v1/proof_keys. If you keep proofs as long-term receipts, store the public key next to them.
  • /v1/executor/keys serves the same keys for the agent.
