Build

Agent tools

Give an AI agent a refund, cancel or email tool keyed to a stable id, so a reworded retry runs once: quarter_tool in Python, quarterTool in TypeScript, with human approval before dispatch.

After a timeout, an agent does not resend its last call. The model reasons again and emits a new call, often with reworded arguments: another amount, a different reason, a rephrased subject. A runtime id does not match it, and a key hashed from the arguments does not match it either, so the refund runs twice.

quarter_tool and quarterTool take the identity from a key you declare, such as refund:order_123. The model's text and the tool call id are never used. A second call for the same key is the same action. If its details differ from the first, Quarter refuses it with ACTION_ID_CONFLICT. In simulator runs, Quarter produced one effect in 40 of 40 reworded-retry runs, and an argument-hash key produced 30 duplicates in 40 runs. These are simulator-tested results, not provider certification.

A support-agent refund tool

The key is a function of the tool arguments and must return the business id. The tool refuses to build without it. input maps the arguments to the ActionSpec input, so the model never supplies the payment intent.

Python also has async_quarter_tool for AsyncQuarter. The result is a plain tool definition plus a call that returns a JSON string, so it also fits the Vercel AI SDK and Anthropic tool use: pass name, description and parameters as the tool definition, and return the call's result as the tool result.

What the model gets back

The tool waits up to 20 seconds (timeout in Python, timeoutMs in TypeScript) and returns status, the action id and a message written for the model. Every message that means "not finished" tells the model not to retry.

StatusWhat the model is told
CONFIRMEDDone, with the provider object id. Do not call again.
NOT_EXECUTEDIt did not happen, and why. Nothing changed.
OUTCOME_UNKNOWN, RECONCILINGIn progress while Quarter proves the outcome. Do not retry. Give a human the action id.
NEEDS_REVIEWHeld for human approval. Do not retry. Tell the user it is awaiting approval.
ACTION_ID_CONFLICTAlready requested with different details. Do not retry. Tell the user what was already requested.
SAFE_TO_RETRYIt did not complete and nothing changed. Safe to retry with the same details.

When the action carries a verdict, the message is the verdict's class and safe next step instead, and the result adds verdict with the class. Unless the verdict is retry-safe, the model is also told not to retry and not to call the tool again for that action.

Approval before dispatch

A review_above policy holds a large refund before anything is sent. The tool returns NEEDS_REVIEW, so the agent tells the customer the refund awaits approval instead of trying again. A person then decides with one call. Approve releases the action for dispatch. Reject ends it as NOT_EXECUTED with the reason REJECTED_BY_REVIEWER.

  • The hold raises an event. Subscribe a webhook to action.approval_required to open a ticket or notify a channel. action.needs_review stays reserved for uncertain outcomes.
  • The approver is in the proof. The credential that approved is recorded on the ledger and written into the signed Outcome Proof as approvedBy.
  • Only policy holds can be approved. An action in review because its outcome is uncertain returns INVALID_MANUAL_RESOLUTION. Resolve that one with evidence instead.
  • After approval, the agent asks again. Its next call under the same key returns the current state of the same action, CONFIRMED once the refund is proven.

On Temporal

When the agent runs on Temporal, put the model call and the tool in separate activities, so Temporal can retry the tool without asking the model again. The tool activity calls quarterAction from @quarterso/workflows with an explicit id built from the order, not the workflow or activity id, so a Temporal retry and a reworded call from the model are the same action.

In the workflow, catch the non-retryable failure and return it to the model as the tool result. ACTION_ID_CONFLICT becomes "already done with other arguments, do not call again", and any other final outcome becomes a message that says it is final. The complete worker and workflow are in examples/temporal-agent-tool in the workflows package.

Find unwrapped tools with ActionLint

The agent-tool-direct-write rule flags a Stripe refund, subscription cancel, payout, transfer or customer update, or a Resend email, called directly inside an agent tool. That covers a tool({ execute }) body from the Vercel AI SDK or OpenAI Agents JS, and an MCP server.tool() or registerTool() handler. The fix is to wrap the write with a Quarter tool keyed on the business intent. ActionLint reads TypeScript and JavaScript only; Python @function_tool code is not parsed. See ActionLint.

Choosing the key

  • Use the business id, such as the order id, and a version suffix such as :v1 you can bump when a second refund on the same order is legitimate.
  • Never use the tool call id, the model's text or a hash of the arguments. Each changes when the model rewords a retry.
  • Keep the amount out of the key. A changed amount under the same key is the case Quarter exists to refuse.
