Get started

Send an action from code

Install the SDK, send a Stripe refund through Quarter from your backend, and read the state it returns.

This guide sends one Stripe refund through Quarter from TypeScript in a sandbox project. You need Node 22 or later. Using Python? The Python SDK has the same calls. To see Quarter handle a lost response first, from the terminal, start with the Quickstart.

Get an API key

Early access teams receive a sandbox project and its first API key. Sandbox keys start with qk_test_; production keys start with qk_live_. A key is shown once, when it is created. Quarter stores only a hash. New sandbox projects are simulated: no provider account is needed.

Put the key and the base URL in the environment. The SDK reads both.

Sandbox projects run provider calls against simulators or with test credentials only. A production project refuses any action whose ActionSpec is not certified, with ACTION_SPEC_NOT_CERTIFIED. See the actions reference for each action's status.

Install the SDK

Send your first action

An action is one business write. Give it an id derived from the business operation, not from the attempt: the refund for order 1042 is always refund:order_1042:v1, however many times your code runs. That id is what makes the write happen at most once. See action identity.

execute validates the input against the action's ActionSpec, applies your policy, compiles a plan, and dispatches it. In managed mode the request waits up to 10 seconds for the action to settle. You can change the wait with ?wait=<ms>, up to 30000.

Read the state

The response is an ActionView. When the action settled with a known outcome, the HTTP status is 200. When it is still open, the status is 202 and state says why. Neither case is an error.

FieldMeaning
stateWhere the action is. Branch on this. See Handling states.
assuranceHow strong the evidence behind the state is. UNRESOLVED until a proof exists.
output.providerObjectIdThe provider object the action created or changed, once CONFIRMED.
proofThe Outcome Proof: the evidence, and the spec and plan it was judged against.
fingerprintHash of action, input and subject. The same id with a different fingerprint is refused.
reasonShort explanation for the current state, when there is one.

Read the action again at any time, or read its full timeline. Every state change is an event in an append-only ledger.

Send it again

Run the same execute call a second time. Quarter returns the existing action and does not call Stripe again. Change amount and send it with the same id: Quarter refuses with ACTION_ID_CONFLICT (409) before anything is dispatched.
