Outcomes

Provider health

Quarter judges each provider as healthy, degraded or failing over 5-minute windows, from your observed calls and your protected actions, and says why.

When a provider starts failing, the first question is whether it is your code or the provider. Provider health answers it from what your project already sends: the call classes of observed calls, and the verdicts of protected actions. It is judged per project, so it reflects the calls you make.

Health is a label for where to look, never evidence about an action. A failing provider does not settle any outcome, and a healthy one does not make a retry safe.

How a window is judged

  • Every 5 minutes, Quarter judges the window that just closed. A window is judged once and never changes afterwards.
  • Calls to a provider's known host are grouped under the provider's name, so api.stripe.com counts as stripe together with Stripe actions. Other hosts are judged by host.
  • A window with too few calls and actions to judge is recorded with enoughData: false and status healthy. Treat it as unknown.
  • Each signal below is a share of the window's calls or actions. Past a threshold the provider is degraded, past a higher one failing. The worst signal sets the status.
  • The thresholds and the minimum sample are served as policy in the response, so the console and your own tools state the same numbers Quarter judges by.
SignalCountsOut of
provider_errorsCalls classed provider_error or lost_responseAll observed calls
throttlingCalls classed throttledAll observed calls
unreachableCalls classed not_dispatchedAll observed calls
unsettled_actionsActions with verdict lost_response, retry_budget_spent or outcome_contradictedAll actions

Calls your side caused, such as rejected_auth, rejected_input, conflict and not_found, say nothing about the provider. They count in the total and never in a signal.

Read current health

GET /v1/providers/health returns each provider's latest judged window. Each reason names the signal, its count, the total and the rate. incident is set while an incident is open.

windowEnd is when the latest judged window closed. A window is recorded only when a provider saw traffic, so a provider you stopped calling keeps its last window. stale: true says so: the status is its last, not its current, and the console shows it as quiet. The full response is in the API reference.
