Get started

Quickstart

Add a vendor, confirm its bank details, upload a small payment run, decide the held payment and get the file back.

This walks one small payment run through Quarter with a test key. It takes six requests. Every response below is the full JSON the api returns.

Before you start

You need a test API key, which starts with qk_test_, and your API URL. During early access, Quarter gives you both. You also need curl and jq.

1. Add a vendor with bank details

A vendor is someone you pay. Give its name, the domain of its email addresses and the bank details you have on file. The details start unverified: nobody has confirmed them with the vendor yet, so payments to them would be held.

The response never repeats the account number. Quarter seals it and shows the last 4 digits. Keep the vendor id and the bank account id.

2. Confirm the bank details

In production you would send the vendor a verification link, where they log in to their own bank. Here, record a call-back instead: someone at your company called the vendor at a number you already had, and the vendor confirmed the details.

3. Upload a payment run

Here is a CSV with two payments: one to Harbor Point, and one to a payee you have never added. Save it as run.csv.

The api takes the file as text inside a JSON body. jq builds that body from the file.

Harbor Point is clear. It carries a warn finding because it is the first payment to this vendor; a warning never holds. J. Reyes Consulting is held, because the payee is not a vendor you know. Every finding has a code you can look up in Checks and a message you can show as it is.

4. Decide the held payment

A person approves or rejects each held payment and says why. The reason and the person go into the audit trail.

5. Release the run

Release works once no payment is still held. It returns the file to upload to your bank: the same CSV, without the rejected row.

A run can be released once. Run the release request one way or the other, not both: the second call gets run_closed. To read the run again later, use GET /v1/payment_runs/{run}.
