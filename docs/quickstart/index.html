Get started

Quickstart

Five minutes in the simulated sandbox: run a Stripe refund, lose its response on purpose, and watch Quarter prove it happened once.

This quickstart uses the quarter CLI against a simulated sandbox project. It needs no provider account. To send actions from your backend instead, see Send an action from code.

1. Get a sandbox key and the CLI

Early access teams receive a sandbox project with a qk_test_ key. The sandbox is simulated: provider calls go to Quarter's provider simulators, so you need no Stripe account and no provider credentials. Build the CLI from the quarterso/cli repository. Node 22 or later.

2. Log in

quarter login saves the key and base URL to ~/.quarter/config.json with mode 0600. QUARTER_API_KEY and QUARTER_API_URL override it.

3. Run a refund

The id names the business operation. The simulated Stripe applies the refund and answers, and Quarter returns CONFIRMED with the refund id in output.providerObjectId.

4. Lose the next response

timeout_after_commit makes the simulated Stripe apply the next write and then never answer. This is the gap where retry code refunds twice.

5. Run a refund again and watch the timeline

execute waits 10 seconds, then returns HTTP 202 with the action still EXECUTING. When the dispatch timeout expires, Quarter marks it OUTCOME_UNKNOWN, starts reconciling, and resends the refund with the same Stripe idempotency key. Stripe replays its stored result instead of refunding again, so the action ends CONFIRMED with PROVIDER_NATIVE assurance. Run quarter listen in a second terminal to see the events arrive.

6. Check what the provider really did

quarter effects stripe prints the simulator's own record, kept apart from anything Quarter concludes. There is one refund per action: refund:order_1043 refunded exactly once, although its response was lost.

7. Verify the proof offline

The Outcome Proof is signed with Ed25519. --verify checks the signature against Quarter's published keys on your machine and exits 1 if it does not verify.

Next steps

  • Try the other faults, such as reset_before_commit and lookup_unavailable: Simulated sandbox and test helpers.
  • Send the same refund from TypeScript: Send an action from code.
  • Send it from Python: Python SDK.
  • Let your coding assistant do this through MCP: Use Quarter from AI coding tools.
