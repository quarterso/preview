Outcomes

Incidents

An incident opens when a provider stays degraded or failing for several windows in a row, and closes after a run of healthy ones. Both send an event.

One bad window is noise. An incident is Quarter's record that a provider stayed unhealthy: when it started, how bad it got, why, and when it ended. It is built from the provider health windows, with hysteresis so it does not flap.

When an incident opens and closes

  • An incident opens after several judged windows in a row at degraded or worse, and closes after several judged healthy in a row. The counts are served as policy.incidents by provider health.
  • A window without enough data neither opens nor closes an incident.
  • A provider you stop calling sends no windows, so its open incident cannot close. The incident then has stale: true and a lastWindowEnd. That means Quarter cannot tell, not that the outage continues. It closes once calls resume and enough healthy windows follow.
  • While open, worstStatus rises to failing if a later window is worse than the one that opened it, and reasons then describe that window.

Events

Opening an incident emits provider.degraded; closing it emits provider.recovered. Both are written in the same transaction as the incident, and are delivered like every other event: to webhooks that subscribe to them, and on the event stream.

List incidents

Filters: state (all by default, open or closed), provider (a name such as stripe, or a host), limit and cursor. See the API reference. The console's Incidents page shows the same list, and coding assistants read it with the quarter_incidents MCP tool.
