Reference

CLI reference

Every quarter command and flag: actions, events, proofs, live event forwarding, fault injection, lint, Spec Import, Evidence Export, and the MCP server.

Install

The CLI is in early access. Build it from the quarterso/cli repository with Node 22 or later.

Configuration

  • quarter login --key qk_test_... --url https://api.example.test writes ~/.quarter/config.json, readable only by you (mode 0600). The key must start with qk_.
  • QUARTER_API_KEY and QUARTER_API_URL override the saved values. QUARTER_CONFIG points at a different config file.
  • Every command except login, lint and help needs a key.
  • Errors print to stderr and exit with code 1.

Commands

CommandWhat it does
login --key qk_... [--url URL]Save the key and base URL to ~/.quarter/config.json.
actions [--state S] [--provider P]The 20 most recent actions, one per line.
action <id>One action as JSON, with its proof.
events <id>An action's timeline: sequence, event type, and state change.
execute --action T --id ID --input JSONRun an action. The actor is recorded as user cli.
proof <id> [--verify]The signed Outcome Proof. With --verify, check it offline.
listen [--forward-to URL] [--events a,b]Stream events. With --forward-to, POST each one to a local URL, signed like a webhook.
fault <provider> <fault> [--times N]Simulated sandbox: make the next provider write misbehave.
effects <provider>Simulated sandbox: what the provider really did.
lint [paths...] [--json]Find unsafe retries and missing idempotency in your code. Offline.
specs draft --openapi FILE|URL --operation ID [--out F]Draft an ActionSpec from an OpenAPI 3.0 or 3.1 operation. See Spec Import.
specs draft --postman FILE --request NAME|ID [--out F]Draft an ActionSpec from a Postman Collection v2.1 request.
export postman <id> [--out F]An action's provider attempts as a Postman Collection v2.1 regression test. See Using Quarter with Postman.
mcpRun the MCP server for AI coding tools over stdio.
help, --versionUsage, and the CLI version.

Actions and proofs

proof --verify fetches the proof and Quarter's public keys, then checks the Ed25519 signature locally. It prints valid: <id> is <state> (<assurance>), signed by <keyId> and exits 0, or prints INVALID and exits 1. See Signed proofs.

listen

quarter listen streams project events as they commit. With --forward-to, it POSTs each event to your local endpoint with a quarter-signature header in the production format (t=<unix seconds>,v1=<hex HMAC-SHA256 of "<t>.<body>">), so your webhook code verifies it unchanged. The signing secret is new for each session and printed at start. --events limits forwarding to a comma-separated list of event types. An event is never forwarded twice in one session, even across stream reconnects.

fault and effects

Only for simulated sandbox projects. quarter fault <provider> <fault> accepts timeout_after_commit, reset_after_commit, error_500_after_commit, error_500_before_commit, reset_before_commit, throttle, lookup_unavailable and version_drift. --times applies it to the next N writes, up to 50. quarter effects <provider> prints the simulator's record of the writes it applied.

lint

quarter lint runs ActionLint over the given files or directories, or the current directory. It prints findings as text, or as JSON with --json, and exits 1 when there is any finding, so it can gate CI. It makes no network calls. See Shadow mode and ActionLint.

specs draft and export postman

quarter specs draft writes a draft ActionSpec to --out or stdout and prints a checklist of what a person must decide to stderr. The draft never passes validation until a person writes its evidence rules. quarter export postman needs a key: it reads the action, its timeline and its installed spec. See Spec Import and Using Quarter with Postman.

mcp

quarter mcp runs an MCP server over stdio for Claude Code, Cursor and other MCP clients. It uses the same key and base URL as the other commands. See Use Quarter from AI coding tools.
