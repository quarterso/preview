Reference

Certification

How Quarter tests each ActionSpec against provider simulators and, with test-mode credentials, against the provider itself, and what each status means.

An ActionSpec is Quarter's reading of a provider's documentation: how duplicates are prevented, and what proves an outcome. Certification checks that reading. It runs the same scenarios against Quarter's simulator and, when test-mode credentials are available, against the provider's own test mode, and logs every place they disagree.

Statuses

StatusWhen
certifiedA run against the provider's test mode passed every scenario that applies, with no open discrepancy.
simulator-testedEvery scenario passed against the simulator. This is the most a simulator run can give.
not certifiedA scenario failed, a discrepancy is open, or no test-mode credentials were available.
blockedThe run refused to start, for example because a key was not a test-mode key.

Simulator-tested means Quarter's model of the provider behaves as the spec says. It is not a claim about how the provider behaves, which only a certified run shows.

Scenarios

Some scenarios can run against a provider's test mode. Each result is judged by the same engine functions that decide real actions.

  • The happy path.
  • A replay with the same idempotency key, and a replay with changed input.
  • Reading the object back after the write.
  • A lost response, then reconciliation through the spec's lookup rules.
  • A lookup of an object that does not exist.

The rest need a fault injected at an exact moment or the simulator's record of what it really applied, so they run against the simulator only: crashes before and after dispatch, timeouts and resets after the provider committed, 5xx and 429 answers, a replay that meets the original still in flight, concurrent duplicates, reworded retries, and a provider serving another API version.

Test-mode credentials only

  • Stripe runs only with sk_test_ or rk_test_ keys.
  • Resend has no test keys, so its runs send only from and to Resend's own test addresses.
  • A live key is refused before anything is sent, and so is a provider with no rule that proves its key cannot reach a live account. The run is marked blocked.

Discrepancies

In a test-mode run, each scenario also runs against the simulator. Any difference in status, error code, replay behaviour, object identity, evidence or the engine's conclusion is logged as a discrepancy. A discrepancy is a finding, not a failed test: either the provider or Quarter's reading of it is wrong. It stays open until the simulator, the adapter or the spec is fixed, and a spec change gets a new version.

Some properties cannot be measured in one run. Stripe and Resend keep an idempotency key for 24 hours, so a run lists the replay window as unverified rather than as passed.
