Outcomes

Events and live streaming

List project events with cursor pagination, or stream them over server-sent events as they commit.

Quarter keeps two kinds of history. Project events (evt_...) are the state changes webhooks deliver, one per transition into a state listed in Webhooks. Action events are the full ledger of one action, including steps that do not change state.

List project events

GET /v1/events returns events newest first. Filter by type, set limit (1 to 200, default 50), and pass nextCursor back as cursor for the next page. nextCursor is null on the last page.

Use this to backfill after your webhook endpoint was down: page back until you reach an event id you already processed.

Stream events

GET /v1/events/stream is a server-sent events stream of project events as they commit. Each message has the event id as id, the event type as event, and the event JSON as data. The server sends a : ping comment every 15 seconds to keep proxies from closing the connection.

  • To resume after a disconnect, reconnect with a Last-Event-ID header set to the last id you received. Quarter first sends up to 500 events that committed after it, oldest first, then continues live. Beyond 500, backfill with GET /v1/events.
  • The SDK's stream does this for you. It remembers the last id it delivered and, when the connection drops or the server closes it, reconnects with Last-Event-ID. Waits between attempts start at 500 ms and double up to maxBackoffMs (default 30000), and reset once an event arrives. Pass lastEventId to resume from an id you stored, or reconnect: false to get one connection only.
  • stream resolves when your signal aborts, or when the stream ends and reconnect is false. It rejects without retrying when the API refuses the stream with a 4xx, such as a revoked key, and after any connection error when reconnect is false. After a long outage, backfill anything past the 500-event replay with list.
  • Authentication is the bearer header. Browsers cannot set headers on EventSource, so proxy the stream through your own server. Never ship an API key to a browser.
  • Use webhooks for work that must happen. Use the stream for dashboards and live views.

One action's timeline

GET /v1/actions/{actionId}/events returns every ledger event for one action, oldest first, with seq starting at 1. Each carries fromState, toState and data, which always includes specVersion, the worker that wrote it and, once compiled, compilerVersion and planHash.
