Build

SDK integrations

wrapStripe for existing Stripe code, executeAndWait for Temporal, Inngest and Trigger.dev steps, and a verified webhook route for Next.js.

wrapStripe

wrapStripe(quarter) takes Stripe's own call shapes and routes them through Quarter. The idempotencyKey you already pass becomes the action id, so it must name the business operation, never a random value per attempt. A call without one throws VALIDATION_FAILED.

MethodAction
refunds.create(params, { idempotencyKey })stripe.refund.create
customers.create(params, { idempotencyKey })stripe.customer.create
customers.update(id, params, { idempotencyKey })stripe.customer.update
subscriptions.cancel(id, params, { idempotencyKey })stripe.subscription.cancel

On CONFIRMED a call returns { id, object, quarter }, where id is the Stripe object id and quarter the full ActionView. Any other state throws QuarterOutcomeError with the view in error.action. Stripe already deduplicates by idempotency key; what the wrapper adds is an answer when the response is lost, a check that still works after Stripe prunes the key, and a proof.

executeAndWait for durable execution

For Temporal, Inngest, Trigger.dev, Restate, DBOS and AWS Lambda durable functions, the recommended path is @quarterso/workflows: it derives the action id from the engine's durable ids and maps each outcome to the engine's retryable or non-retryable error. See Workflow engines. executeAndWait remains for custom setups.

Durable-execution runtimes retry a step that throws, and their own docs leave external side effects to your idempotency. executeAndWait(quarter, intent, { timeoutMs, pollMs }) executes and polls until the action settles (CONFIRMED, NOT_EXECUTED, NEEDS_REVIEW or COMPENSATED). It resubmits on SAFE_TO_RETRY. If the outcome is still open at timeoutMs (default 60000), it throws QuarterPendingError, and the runtime's retry runs the same intent again, which is the same action. Poll interval defaults to 500 ms.

Derive the action id from the workflow's input, never from the run or attempt id. A NEEDS_REVIEW result is returned, not thrown: retrying cannot settle it, a person has to.

Next.js webhook route

quarterWebhookHandler(secret, handle) returns a Fetch API route handler for the App Router. It reads the raw body, verifies the quarter-signature header, and only then calls your function. A bad signature answers 400. When your function returns, it answers 204. If it throws, the route fails and Quarter retries the delivery, so make the handler safe to run twice: dedupe by event.id.

It works in any runtime with the Fetch API Request and Response, including route handlers on the edge. During development, quarter listen --forward-to http://localhost:3000/api/quarter delivers events signed the same way; use the secret it prints. See Webhooks for the event shapes.
