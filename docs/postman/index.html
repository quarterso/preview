Using Quarter with Postman

Postman at design and test time, Quarter at run time. Spec Import drafts an ActionSpec from a collection request; Evidence Export turns a settled action into a collection you can rerun as a regression test.

Teams design and test their API calls in Postman. Quarter runs the consequential ones in production and settles what each did. The two meet at files in your repository: a collection goes in, and evidence comes back out as a collection.

DirectionCommandWhat you get
In: Spec Importquarter specs draft --postman FILE --request NAMEA draft ActionSpec for one write, with the evidence rules left for a person.
Out: Evidence Exportquarter export postman <actionId>A Postman Collection v2.1 with one request per provider attempt and tests for the settled outcome.

Spec Import

Export your collection as Collection v2.1, then name the request that performs the write. The draft takes the method, the path (turning :id and {{id}} into template fields), the example body as the input schema, and an idempotency header if the request sends one. The full flow and the checklist are in Spec Import.

Evidence Export

Pick an action Quarter has settled, such as a refund whose response was lost and which Quarter then confirmed with the provider. The export writes a collection you can commit and run in Postman or its CLI runner.

  • One request per provider attempt, named with how that attempt ended, such as a timeout or a status code.
  • Tests for the settled outcome. CONFIRMED checks for a 2xx and, when known, the provider object id. NOT_EXECUTED checks for a 4xx. An unsettled state asserts nothing, and says so.
  • The evidence in the description: the action id, its state and assurance, the proof hash, and the command to verify the signed proof offline.
  • No secrets and no data. The API key, the idempotency key and every input field are {{variables}} you fill in. Provider response bodies are not exported.

The action view does not include the compiled plan, so the method and endpoint come from the action's installed spec. When that spec's version differs from the one the action ran under, the description says so.

WhenDesign and test timeRun time
UnitA request in a collectionAn action with your business id
