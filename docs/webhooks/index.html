Webhooks

Event types, the signed delivery format, how to verify Quarter-Signature, and how retries and replays work.

Quarter records every change as an event and sends it to your webhook endpoints. The event and its deliveries are written in the same transaction, so an event is never recorded without its webhooks, and a webhook is never sent for a change that did not happen.

Most apps need only access.changed. It fires whenever the set of active entitlements for a user changes, whatever the store and whatever the reason.

What a delivery looks like

A POST with a JSON body, and these headers: quarter-event-id, quarter-timestamp and quarter-signature.

Verify the signature

quarter-signature is t=<timestamp>,v1=<signature>, where the signature is the hex HMAC SHA-256 of <timestamp>.<raw body> keyed with your endpoint's whsec_ secret. Compute it over the raw body before parsing it, and compare in constant time.

Each attempt is signed with the time it was sent, so you can also refuse signatures older than a few minutes.

Retries and replay

  • Any 2xx response counts as delivered. Anything else, a timeout after 10 seconds, or a redirect counts as a failure.
  • A failed delivery is retried with growing waits, up to 8 attempts, then marked failed.
  • You can send any delivery again with POST /v1/webhook_deliveries/{id}/retry.
  • Because of retries, an event can arrive more than once. Use the event id to do the work once.

Endpoints

Register endpoints with POST /v1/webhook_endpoints. An endpoint receives every event type unless you list the ones it wants in enabled_events. The URL must be public and use https.
