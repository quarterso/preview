Outcomes

Webhooks

Receive a signed POST when an action changes state. Verify the signature, answer fast, and dedupe by event id.

Quarter emits an event when an action enters a state your code cares about, and delivers it to every enabled webhook endpoint that subscribes to its type. The event and its deliveries are written in the same transaction as the state change, so an event is never lost and never sent for a change that did not commit.

Event types

TypeSent when the action enters
action.confirmedCONFIRMED
action.not_executedNOT_EXECUTED
action.outcome_unknownOUTCOME_UNKNOWN
action.needs_reviewNEEDS_REVIEW because the outcome is uncertain
action.approval_requiredNEEDS_REVIEW because a policy such as review_above holds the action before dispatch. Answer it with approve or reject
action.safe_to_retrySAFE_TO_RETRY
action.compensatedCOMPENSATED

Operations and providers have events too: operation.* when an operation ends, and provider.degraded and provider.recovered when a provider incident opens and closes.

Create an endpoint

Pass the URL and the event types to send, or ["*"] for all (the default). The response contains the signing secret. It is shown once; store it in your secret manager.

GET /v1/webhook_endpoints lists endpoints, newest first and paged, with their delivery counts (succeeded, failed, pending). PATCH /v1/webhook_endpoints/{id} with {"enabled": false} disables one and pending deliveries to it pause; {"enabled": true} enables it again. DELETE /v1/webhook_endpoints/{id} deletes it with any deliveries still queued. In the SDK: quarter.webhookEndpoints.disable, enable and delete.

The delivery

Each delivery is a POST with a JSON body and these headers: content-type: application/json, user-agent: Quarter-Webhooks/1, and quarter-signature.

The event says which action changed and to what. It does not carry the proof or the provider output. Fetch the action with GET /v1/actions/{actionId} when you need them; that also gives you the current state if later events have already arrived.

Verify the signature

The header has the form t=<unix seconds>,v1=<hex>. v1 is the HMAC-SHA256 of <t>.<raw body> keyed with the endpoint secret. Verify against the exact bytes you received: parsing and re-serializing the JSON changes them. Reject a timestamp more than 300 seconds from your clock, which blocks replays of captured requests.

With the SDK

Quarter.webhooks.constructEvent checks the timestamp and signature in constant time and returns the parsed event, or throws QuarterSignatureError. It needs no API key.

With node:crypto

Retries

Any 2xx response within 10 seconds counts as delivered. Any other status, a connection error or a timeout is a failure, and Quarter tries again with exponential backoff: 20 seconds after the first failure, then 40, 80 and so on, capped at 6 hours between attempts. After 12 failed attempts (about 11 hours) the delivery is marked failed.

  • Answer quickly. Verify, store or enqueue the event, and return 2xx. Do the work afterwards.
  • Deliveries are not ordered. A retry of an older event can arrive after a newer one. Compare with the action's current state rather than trusting arrival order.
  • If your endpoint was down longer than the retry window, backfill with GET /v1/events. See Events and streaming.

Dedupe by event id

Delivery is at least once. A delivery that succeeded on your side but whose response Quarter never received is sent again. Record each event.id you process and skip ids you have seen, in the same transaction as the work the event triggers.
