Build

Workflow engines

@quarterso/workflows turns one provider write into a step that Temporal, Inngest, Trigger.dev, Restate, DBOS or AWS Lambda durable functions can retry safely.

A durable-execution engine retries a step that fails. That is safe for your own code and unsafe for a provider write whose response was lost: the refund may already exist. The engine cannot tell, and its docs leave external side effects to your idempotency. Quarter answers the question the retry needs.

  • The action id comes from the engine's durable ids, for example the workflow id plus the activity id. A retried step sends the same id, so it is the same Quarter action and cannot execute twice.
  • An unproven outcome is retryable. While Quarter reconciles a lost response, the step throws the engine's retryable error. The next attempt asks about the same action instead of sending a second write.
  • A definitive outcome is not. NOT_EXECUTED, NEEDS_REVIEW and COMPENSATED throw the engine's non-retryable error, because retrying cannot change them. CONFIRMED returns the ActionView.

Each adapter waits up to timeoutMs (default 30000) for a settled state, polling every pollMs (default 500). It resubmits on SAFE_TO_RETRY. A transport error to Quarter is also handed back as retryable, since asking again with the same id is how to find out whether the request arrived.

Install

@quarterso/workflows needs Node 22 or later and depends on @quarterso/sdk. Each engine's SDK is an optional peer dependency, so install only the one you use and import its subpath. The examples below share one client.

Imports are subpaths of @quarterso/workflows. step is an action intent with id and actor optional. The default actor is { type: "workflow", id: <engine> }; Temporal uses the workflow type.

When to pass an explicit id

The default id names one run of one step. Pass id, derived from the business operation (for example refund:${orderId}), whenever that operation can span runs:

  • Cron workflows, where every run is a new operation that may repeat an earlier one.
  • Continue-as-new, where the work carries on under a new run.
  • Several functions reacting to the same event, which would otherwise each get their own id.
  • Always on AWS Lambda durable functions. The SDK does not expose the execution id to steps, so the adapter requires id.

Examples

Each example refunds an order once. On return the action is CONFIRMED; every other outcome throws as the table above describes.

Temporal

Register the activities on the worker and proxy quarterAction in the workflow. The activity heartbeats while it waits, so set a heartbeatTimeout if you want Temporal to detect a stuck worker.

Verified end to end

On 2026-09-29, against the real Quarter API with a simulated sandbox provider, a Temporal activity lost its provider response. The activity retried twice while Quarter reconciled, then returned CONFIRMED with provider-native proof. The provider recorded exactly one refund.
