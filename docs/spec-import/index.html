Build

Spec Import

Draft an ActionSpec from an OpenAPI operation or a Postman collection request with quarter specs draft. The draft covers dispatch and identity; a person writes the evidence rules before it can pass validation.

An ActionSpec has two halves. The mechanical half says how to send the write: method, endpoint, input schema, idempotency header. The judgement half says how to prove what happened when a response is lost: which provider read settles the outcome, and what each answer means. Spec Import drafts the first half from a document you already have and leaves the second half to a person.

Draft from OpenAPI

Pass an OpenAPI 3.0 or 3.1 document, as JSON or YAML, from a file or a URL, and the operationId of the write.

Draft from a Postman collection

Pass a Postman Collection v2.1 file and the request's name or id. Export the collection as Collection v2.1 first; other versions are refused.

--provider and --action override the names the draft would pick. Without --out, the draft goes to stdout. Either way, the checklist goes to stderr.

What the draft fills in

  • Provider and action names, and the provider API version from the document.
  • inputSchema, from the path parameters and the request body (the example body, for a Postman request).
  • Dispatch: method and endpoint template, one request in flight per action, 3 attempts, a 30 second timeout.
  • The idempotency header, when the API declares one or its description names one.
  • Retry rules that never retry an ambiguous write automatically.
  • status: "experimental", and the source documentation links it found.

What a person must decide

Every field a person owns is marked "TODO: human", and the reconciliation budget is 0. The CLI prints this checklist:

  1. Which provider read proves the outcome: fill reconciliation and evidenceRules with a lookup by id, a lookup by business key, or an idempotency replay.
  2. How long the provider keeps an idempotency key: set identity.providerKeyLifetimeMs from its documentation.
  3. Whether a 409 means rejected (NOT_EXECUTED) or still in flight (reconcile), and the reliabilityClass that follows.
  4. The reconciliation budget: maxProviderCalls stays 0 until you set it.
  5. Then a lab run in the simulated sandbox before the spec ships.
A draft never passes validation until a person writes the evidence rules. The engine's checkSpec refuses it while any TODO: human remains. That is deliberate: an evidence rule decides whether a lost write is reported as done or not done, and Quarter does not let a generator make that call.

Why only half

An OpenAPI document or a collection describes the request. It does not say which read proves a refund exists, how long an idempotency key lasts, or what a 409 means for this endpoint. Those answers come from the provider's documentation and from testing faults against it, which is why they stay with a person and the lab. Spec Import saves the typing, not the judgement.

To send evidence the other way, from a settled action to a Postman regression test, see Using Quarter with Postman.
