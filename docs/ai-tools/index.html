Build

Use Quarter from AI coding tools

Give Claude Code, Cursor and other MCP clients Quarter's ActionSpecs, a linter and a sandbox, and point them at these docs as Markdown.

Coding assistants write provider calls with a retry wrapper and a fresh idempotency key per attempt, which is how a lost response becomes a second refund. quarter mcp lets the assistant check that code, read how each provider write is protected, and try the write in a sandbox before it ships.

Set up

Install the CLI and run quarter login with a sandbox key. The MCP server reads the same ~/.quarter/config.json, so the client config needs no key.

Claude Code

The command adds the server for you. To share it with a repository, add --scope project, or commit the .mcp.json above at the repository root.

Cursor

Add the server to .cursor/mcp.json in the project, or to ~/.cursor/mcp.json for every project.

Without quarter login

Pass the key and base URL as environment variables instead. Do not commit a file that contains a key.

Tools

ToolWhat it does
quarter_lint_codeRuns ActionLint on a source file: unsafe retries, missing idempotency, fire-and-forget writes. Works offline.
quarter_list_actionsLists the provider writes Quarter protects, with reliability class and status.
quarter_get_action_specThe full ActionSpec for one action type: input schema, duplicate prevention, what proves the outcome, known limitations.
quarter_integration_snippetTypeScript that performs one action through Quarter, built from its input schema, with a stable id and a switch on the state.
quarter_get_actionCurrent state, assurance and proof of one action by id.
quarter_explain_actionWhat happened to one action: its state, its verdict (failure class and safe next step) and a timeline summary. Read-only.
quarter_provider_healthEach provider's current health, with the reasons and any open incident. Read-only.
quarter_incidentsOpen and recent incidents: when a provider started and stopped failing, and why. Read-only.
quarter_recent_failuresRecent observed calls that did not succeed, newest first, with counts by call class. Read-only.
quarter_driftOpen drift leads: provider responses whose shape changed from the route's baseline. Read-only.
quarter_resolve_driftAccepts a drift lead's new shape as the route's baseline. It changes Quarter state and is audited, so the tool asks the assistant to use it only with your agreement.
quarter_list_recipesLists the recipes: business actions that run several provider writes as one operation.
quarter_recipe_snippetTypeScript that runs one recipe through Quarter with a stable id.
quarter_execute_sandboxExecutes an action in a sandbox project, recorded with actor agent mcp. Refused with a live key.
quarter_run_recipe_sandboxRuns a recipe in a sandbox project. Refused with a live key.
quarter_execute_sandbox and quarter_run_recipe_sandbox refuse to run when the configured key starts with qk_live_. An assistant can try writes against a sandbox, which is simulated by default. It cannot move real money. quarter_resolve_drift changes which response shape Quarter expects and nothing else. Every other tool only reads.

Prompts that work

  • Lint src/billing/refund.ts with Quarter and fix what it finds.
  • Write the Shopify refund for an order through Quarter, using the integration snippet.
  • Run a stripe.refund.create in the Quarter sandbox with id refund:order_1042 and show me the proof.
  • My Stripe refunds started failing. Check Quarter for a provider incident or drift before changing the code.

Docs as Markdown

  • /llms.txt lists every docs page with a one-line description.
  • /llms-full.txt is the whole documentation in one Markdown file.
  • Every docs page has a Markdown twin: add .md to its path, for example /docs/quickstart.md. The overview is /docs.md.

The Markdown is generated from the same source as these pages, so it never lags behind them.
