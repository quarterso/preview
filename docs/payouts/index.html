Payouts

For platforms that pay out to their own users: check each payout before it is sent, and get allow, review or block with the reasons.

View as Markdown
The payouts API is built and tested. It has not yet been used by a platform.

A marketplace paying sellers, a gig platform paying workers or a payroll tool calls Quarter before each payout. Quarter answers allow, review or block, with the reasons. Holds, decisions, two-person approval, the audit trail and webhooks are the same as for any payment run. Quarter never sends the money: you do, once the answer is allow.

The model

  • A connected account is one of your own users that you pay out for, named by your external_id, unique in the project.
  • A payee is who a connected account's payouts go to. A payee is a vendor of the project reached only through that account's payouts, so it also appears in /v1/vendors and shares the vendors' external_id space. A payee is a person by default (individual: true).
  • Bank detail changes keep history: new details replace the old ones, which stay on file. A payout within 72 hours of a change holds as payout_details_changed.
  • A payout is a payment run of format payout, or payout_batch for up to 1,000. The payout id is the payment item id.

Decisions

DecisionMeans
allowClear, or a person approved it. Send it.
reviewHeld until a person decides at /v1/payment_runs/{run_id}/items/{id}/decision. payout.reviewed says the outcome.
blockDo not send it: the payee is blocked, a sanctions match was found (payee, wallet or connected account), or a person rejected it.

The checks on a payout

Four checks run only on payouts: payout_details_changed, payout_new_payee_large, payout_account_fan_in and payout_velocity_spike. sanctions_match also looks at the connected account's name.

Some vendor checks do not run on payouts, because your payees change their own details in your app and nobody calls them back: unverified_account, account_changed_recently, shared_account, first_payment, vendor_new_paid_fast, the three request_domain_* checks and just_under_threshold. A payout must name a payee of that connected account, or it is refused with 404 payee_not_found, so unknown_payee never fires.

Idempotency

Every check and batch needs an Idempotency-Key header of 1 to 255 printable characters, unique to the payout or batch. A retry with the same key and the same body gets the first answer back with 200. The same key with a different body answers 409 idempotency_key_reused. Without the header: 400 idempotency_key_required.

Outcomes and the network

  • Report what became of a payout, such as one that left and was later found to be fraud. An API key may record it.
  • Only a signed-in approver's report reaches the network, and only for a business payee at a US account, from a live project, within 10 fraud reports per organization per day. Payees are people by default, so most payout reports stay with you.
  • When an API key reports fraud, the answer says network.shared: false with reason: needs_signed_in_approver. A person sends the same outcome again to share it.

Webhooks

When a person decides a held payout, payout.reviewed is sent with payout_id (the payout, as GET /v1/payouts/{payout} takes it), run_id (the check or batch it came in), item_id (the same as payout_id), decision (allow or block), reviewed_by and reason. payment_item.held and payment_run.released fire as for any run. See webhooks.

Limits

  • Each credential may send 600 requests a minute, and a project 30 batches a minute: at most 600 single checks, or 30,000 payouts in batches, per key per minute.
  • Integration keys and approvers signed in may write; viewers may read. Agent keys cannot call these routes.
  • Payee bank details on file are US accounts only: a 9-digit routing number and an account number. An IBAN payout therefore holds as account_not_on_file.
  • In live mode, payees count toward active_vendors on your plan.

Endpoints

Create a connected account

POST/v1/connected_accountsAuth: API key

Errors: 400 external_id_invalid, name_invalid; 409 external_id_taken.

Body

FieldTypeRequiredDescription
external_idstringYesYour id for the account, unique in the project.
namestringYesUp to 200 characters.

List connected accounts

GET/v1/connected_accountsAuth: API key

Oldest first. limit is 1 to 200, 50 by default; pass the last id as after for the next page.

Query parameters

FieldTypeRequiredDescription
limitintegerNo1 to 200, 50 by default.
afterstringNoThe id of the last account on the previous page.

Retrieve a connected account

GET/v1/connected_accounts/{account}Auth: API key

Unknown: 404 connected_account_not_found.

Path parameters

FieldTypeRequiredDescription
accountstringYesQuarter's id (cac_) or your external_id.

Create a payee

POST/v1/connected_accounts/{account}/payeesAuth: API key

A payee of the connected account, optionally with bank details. The answer is the payee as a vendor with object: payee and connected_account_id; bank_accounts keeps every account it has had.

Path parameters

FieldTypeRequiredDescription
accountstringYesQuarter's id (cac_) or your external_id.

Body

FieldTypeRequiredDescription
namestringYesThe payee's name.
external_idstringNoYour id for the payee, unique in the project.
individualbooleanNoTrue by default for a payee: the network never takes or gives facts about a person.
routing_numberstringNo9 digits.
account_numberstringNo4 to 17 letters or digits.
holder_namestringNoThe account holder.

Retrieve a payee

GET/v1/connected_accounts/{account}/payees/{payee}Auth: API key

The payee with its bank detail history. Unknown: 404 payee_not_found.

Path parameters

FieldTypeRequiredDescription
accountstringYesQuarter's id (cac_) or your external_id.
payeestringYesQuarter's id (ven_) or your external_id.

Change a payee's bank details

PUT/v1/connected_accounts/{account}/payees/{payee}/bank_accountAuth: API key

The old details stay as history. A payout within 72 hours holds as payout_details_changed.

Path parameters

FieldTypeRequiredDescription
accountstringYesQuarter's id (cac_) or your external_id.
payeestringYesQuarter's id (ven_) or your external_id.

Body

FieldTypeRequiredDescription
routing_numberstringYes9 digits.
account_numberstringYes4 to 17 letters or digits.
holder_namestringNoThe account holder.

Check a payout

POST/v1/payouts/checkAuth: API key

Checks one payout before it is sent and answers at once. 201 the first time, 200 for a retry under the same key. A payout with nothing held is released at once; a held one waits for a person.

Errors: 400 idempotency_key_required, connected_account_required, payee_required, rail_invalid and the payment check field errors; 404 connected_account_not_found, payee_not_found; 409 idempotency_key_reused.

Body

FieldTypeRequiredDescription
connected_accountstringYesQuarter's id or yours for the connected account.
payeestringYesQuarter's id or yours for the connected account's payee.
railstringYesach, wire, rtp, fednow, international or stablecoin.
amountnumberYesIn major units.
currencystringNoThree letters; USD unless the rail is international.
routing_numberstringNo9 digits; ach, wire, rtp and fednow.
account_numberstringNo4 to 17 letters or digits; ach, wire, rtp and fednow.
ibanstringNoInternational only.
bicstringNoInternational only.
networkstringNoStablecoin only.
addressstringNoStablecoin only: the wallet paid.
referencestringNoYour id for the payout.

Check a batch of payouts

POST/v1/payouts/batchesAuth: API key

Checks 1 to 1,000 payouts under one Idempotency-Key. Earlier payouts in the batch count toward the fan-in and velocity of later ones. 30 batches a minute per project.

Errors: 400 payouts_invalid, idempotency_key_required, and any payout error prefixed with its index, such as payouts[3]; 409 idempotency_key_reused; 429 over the batch limit.

Body

FieldTypeRequiredDescription
payoutsarrayYes1 to 1,000 payouts, each with the fields of a single check.

Retrieve a batch

GET/v1/payouts/batches/{batch}Auth: API key

The batch with each payout as it stands. Unknown: 404 payout_batch_not_found.

Path parameters

FieldTypeRequiredDescription
batchstringYesThe batch id, starting with run_.

Retrieve a payout

GET/v1/payouts/{payout}Auth: API key

Its current decision, and the review once a person made one. Unknown: 404 payout_not_found.

Path parameters

FieldTypeRequiredDescription
payoutstringYesThe payout id, starting with itm_.

Report what became of a payout

POST/v1/payouts/{payout}/outcomeAuth: API key, or a signed-in approver

Takes the same body as recording what a payment was. An API key records it; a signed-in approver reporting a fraud_attempt about a business payee at a US account also reports it to the network, within the daily limit. network.reason is not_fraud, needs_signed_in_approver, individual_payee, not_a_us_account or daily_limit when it was not shared.

Path parameters

FieldTypeRequiredDescription
payoutstringYesThe payout id, starting with itm_.
