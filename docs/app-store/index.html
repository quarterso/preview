Connect stores

Connecting the App Store

Connect the App Store, report Apple's signed transactions from your app, and point App Store Server Notifications at Quarter.

Quarter trusts only what Apple signed. Every transaction and notification is checked against Apple's certificates and your bundle id before anything unlocks.

1. Add the App Store source

Give Quarter your bundle id. Add your App Store Server API key, key id and issuer id too, so Quarter can ask Apple for the latest state of a subscription when it needs to. app_apple_id is required by Apple for production data.

2. Point notifications at Quarter

In App Store Connect, set the App Store Server Notifications URL (version 2) to the notifications_url from the response, for production and for sandbox. It is the same as setup_urls.app_store.

3. Report purchases from your app

When StoreKit completes a purchase, and again when the user restores purchases, send the signed transaction (its JWS representation) to your backend, and from there to Quarter with your user id.

Keep your API key on your server. Never put it in the app itself.

Products and credits

A product's store_product_id is the App Store product id. Credits bought through the App Store never expire, whatever the product says, because Apple requires that in-app purchases of credits do not.
