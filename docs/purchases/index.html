API reference

Purchases

Report a purchase from your app as soon as the store completes it, and again on restore.

Send your API key as authorization: Bearer <key> and JSON bodies as content-type: application/json. Errors use the shape in Errors.

Report a purchase

POST/v1/apps/{app}/purchasesAuth: API key

Your app reports a purchase as soon as the store completes it, and again when the user restores purchases. Quarter verifies it with the store, applies it once, and answers with the user's access. Reporting the same purchase again changes nothing.

Send the field that matches source: signed_transaction, purchase_token, or checkout_session_id. A Google Play one-time product also needs product_id.

Path parameters

FieldTypeRequiredDescription
appstringYesThe app id, starting with app_.

Body

FieldTypeRequiredDescription
userstringYesYour id for the user who bought.
sourcestringYesstripe, app_store or play_store.
signed_transactionstringNoFor app_store: the transaction's JWS, as StoreKit gives it.
purchase_tokenstringNoFor play_store: the purchase token from Google Play Billing.
product_idstringNoFor a play_store one-time product: its product id. Leave it out for a subscription.
checkout_session_idstringNoFor stripe: the Checkout Session id. It must have been created with your user id as client_reference_id.

If the store does not know the purchase, the request fails with purchase_not_verified and nothing changes. A Stripe session paid by another user fails with user_mismatch.
