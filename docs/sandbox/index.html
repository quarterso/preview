Build

Simulated sandbox and test helpers

Sandbox projects run against provider simulators. Inject faults into the next provider call and read what the provider really did.

A new sandbox project is simulated by default. Provider calls go to Quarter's simulators instead of the real APIs, so you can try every action without a provider account or credentials. Each project gets its own simulator per provider: objects you create and faults you inject are visible only to that project. Production projects never use simulators.

The simulators implement the endpoints each ActionSpec uses, including the provider's idempotency replay and the lookups reconciliation relies on. Each one records its own ground truth, the effects it applied, independently of anything Quarter concludes. Provider Lab uses the same simulators.

Inject a fault

A fault applies to the next write to that provider, or to the next times writes (1 to 50). Faults queue in the order you inject them. lookup_unavailable applies to reads instead.

Faults

FaultWhat the simulated provider does
timeout_after_commitApplies the write, then never answers. Quarter's dispatch times out: OUTCOME_UNKNOWN, then reconciliation.
reset_after_commitApplies the write, then drops the connection.
error_500_after_commitApplies the write, then answers 500.
error_500_before_commitAnswers 500 without applying the write.
reset_before_commitDrops the connection without applying the write.
throttleAnswers 429 with retry-after, without applying the write.
lookup_unavailableFails the next reads, so reconciliation lookups cannot see the provider.
version_driftApplies the write and answers with an API version the ActionSpec is not pinned to.

Read what really happened

GET /v1/test_helpers/effects?provider=<id> returns the simulator's record of every write it applied. ref is the idempotency key or client id Quarter sent, objectId the provider object. Compare it with Quarter's answer: a CONFIRMED action has exactly one effect, a NOT_EXECUTED action has none.

Use it in tests

Test helpers make your own integration tests exercise the lost-response path. This test injects a timeout and checks that your code ends with one refund.

Limits

  • Test helpers answer VALIDATION_FAILED on a project that is not simulated, and RESOURCE_NOT_FOUND for a provider with no ActionSpec.
  • Simulators model the documented behavior Quarter depends on. They are not the provider. Results against simulators are not certification; see How providers are supported.
