How it works

What happens when a refund's response is lost.

One Stripe refund, followed from your code to a confirmed answer. The connection drops after Stripe has already acted.

The path

Six steps, each one written to the ledger.

  1. Intent

    Your code sends the write with an ID like refund:order_4821:v1.

  2. Policy

    Your rules decide whether it may run.

  3. Plan

    Quarter works out how to send it and how to check it.

  4. Dispatch

    One attempt at a time. Never two at once.

  5. Evidence

    Every response and lookup is recorded.

  6. Outcome

    A proven answer, or a person decides.

Worked example

refund:order_4821:v1, step by step.

$129.00 back to the customer, once. Timings are illustrative.

  1. 0 ms
    CREATED

    Your code sends the refund

    billing-api calls quarter.actions.execute for order 4821. Quarter stores a fingerprint of the input.

    id: "refund:order_4821:v1" · action: "stripe.refund.create" · amount: 12900
  2. 3 ms
    AUTHORIZED

    Validated and allowed

    The input is valid and your policy allows the refund.

  3. 5 ms
    AUTHORIZED

    Plan compiled

    The Stripe Idempotency-Key comes from the action ID. If the response is lost: replay the key, then search by metadata. At most 5 calls in 90 seconds.

    planHash sha256:9f3c…a41e
  4. 9 ms
    EXECUTING

    One attempt, under a lease

    The executor sends POST /v1/refunds with the key. A second call with the same ID waits instead of sending.

  5. 10.0 s
    OUTCOME_UNKNOWN

    Stripe refunds the payment. The response never arrives

    The connection resets after Stripe has acted. Nothing retries. If your code is still waiting, it gets HTTP 202 with this state.

  6. 11.0 s
    RECONCILING

    Check 1: replay the key

    Stripe answers 503. That proves nothing, so Quarter tries the next check.

  7. 13.1 s
    RECONCILING

    Check 2: look up by business key

    Quarter finds refund re_3Qx…7Lk by the metadata it attached.

  8. 13.1 s
    CONFIRMED

    Confirmed, with proof

    Quarter signs a proof naming the Stripe refund. Any later call with the same ID returns this answer. There is no second refund.

The same refund could also have ended as

NOT_EXECUTED

Stripe rejected the refund, for example because the charge was already refunded.

NEEDS_REVIEW

No check found proof within 5 calls and 90 seconds. A person decides, with the evidence in front of them.

States

OUTCOME_UNKNOWN is its own state, never a failure.

A false CONFIRMED is the worst bug Quarter can have, so unknown is always allowed.

Response lost, refund found by lookup: confirmed with deterministic evidence.

StateMeaningAutomatic retry
CREATEDQuarter has the requestNo provider attempt yet
VALIDATEDThe input is validNot applicable
AUTHORIZEDYour policy allows itNot applicable
EXECUTINGBeing sent to the providerNo concurrent duplicate attempt
CONFIRMEDIt happened, with proofNo
NOT_EXECUTEDIt did not happen, with proofAccording to plan
OUTCOME_UNKNOWNIt may have happenedNo
RECONCILINGQuarter is asking the providerNo
SAFE_TO_RETRYProven safe to send againYes
NEEDS_REVIEWA person decidesHuman or provider-specific
COMPENSATINGBeing undoneNo
COMPENSATEDUndoneTerminal, with audit trail

Reliability classes

What Quarter can promise for each action.

It depends on what the provider offers. One provider can have actions in several classes.

AR0ObservedRecorded, with no promise beyond that.No actions
AR1Duplicate-resistantTwo copies never run at once, and retries keep the same identity.2 actions
AR2Retry-safeThe provider absorbs a repeated request, so a retry is harmless.1 action
AR3ReconcilableAfter a lost response, Quarter can prove what happened by asking the provider.55 actions
AR4RecoverableProvable, and Quarter can undo it.No actions

Evidence levels

How each answer was reached.

Every proof names one. No confidence percentages, and no language model decides an outcome.

PROVIDER_NATIVE
The provider's own idempotency proves it.
DETERMINISTIC_RECONCILIATION
A lookup at the provider proves it.
HEURISTIC_RECONCILIATION
Evidence points one way but cannot prove it. Never settles on its own.
MANUAL
A person resolved it, with the evidence attached.
UNRESOLVED
No safe answer yet.
