API & SDK

Call Quarter where you called Stripe.

Send the write with a stable ID. Quarter runs it once and answers with a state. TypeScript and Python.

Quickstart API reference
refund.ts
1const result = await quarter.actions.execute({2  id: `refund:${order.id}:v1`,3  action: "stripe.refund.create",4  actor: { type: "service", id: "billing-api" },5  input: { paymentIntent: order.paymentIntent, amount: 12900 },6});7// result.state: CONFIRMED, NOT_EXECUTED,8// SAFE_TO_RETRY, NEEDS_REVIEW or OUTCOME_UNKNOWN

One call replaces the provider call and the retry helper.

Before: Stripe call plus a retry helper

  1. Each attempt mints a new idempotency key
  2. Stripe applies the refund, the response is lost
  3. The helper retries with a fresh key
  4. Stripe sees a new request and refunds again

After: one Quarter call

  1. The ID names the refund, not the attempt
  2. Stripe applies the refund, the response is lost
  3. Quarter checks Stripe instead of guessing
  4. CONFIRMED, with the Stripe refund named in the proof

Branch on the answer.

Workflow engines docs

  • A state, not an error string

    CONFIRMED, NOT_EXECUTED, SAFE_TO_RETRY, OUTCOME_UNKNOWN or NEEDS_REVIEW.

  • Writes never retry inside the SDK

    Lost Quarter's reply? Resend the same ID. You get the same action back.

  • A changed payload is refused

    The same ID with a different input returns 409 ACTION_ID_CONFLICT and dispatches nothing.

  • Workflow engines retry safely

    Temporal, Inngest, Trigger.dev, Restate, DBOS and Lambda durable functions: a retried step is the same action.
