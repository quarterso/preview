Observed calls and verdicts

Know which calls failed, and what is safe to do next.

One line in the SDK records the provider calls your code already makes. See which failed, and whether a retry is safe.

A lost refund, first observed, then settled.

  1. 1. Observed call
    call
    POST /v1/refunds
    error
    UND_ERR_SOCKET
    duration
    30004 ms
    business id
    refund:order_1043
  2. 2. Call classlost_response

    A write that ended without an answer. It may have happened, so a blind retry could refund twice.

  3. 3. Verdict, once protectedsettled_after_lost_response
    retrySafe
    false

    Quarter asked the provider before any retry: the refund exists. Do not retry.

Observing a call does not protect it. Only a write sent through Quarter is retry-safe. Simulator-tested, not certified.

In process, and fail-open.

Node observes global fetch. Python hooks your httpx client.

  • Never in the call path

    No proxy or gateway. Batches are sent in the background and dropped if Quarter is down.

  • Metadata, never contents

    Method, route, status and timing, for the hosts you name. No bodies, query strings or header values.

  • Kept for 30 days

    Filter by provider, class, status, time or business id with GET /v1/calls.

  • A verdict on every protected action

    What happened, whether a retry is safe, and the next step, from recorded evidence only.
