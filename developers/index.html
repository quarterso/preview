Developers

Access and credits, as one API call.

Your app never parses a receipt or puts webhooks in order. Report the purchase, ask what the user has, and spend credits atomically.

Quickstart See the code

A few small pieces of code.

  1. Pass your user id to the store

    Set client_reference_id on the Stripe Checkout Session, or report App Store and Play purchases with it.

  2. Report the purchase

    From your success page or your app. Quarter checks it with the store and answers with the new access.

  3. Ask what the user has

    One GET before you show a paid feature.

  4. Charge for AI calls

    Hold credits before the call and spend what it used. A failed call costs nothing.

  5. Or read your own table

    Turn on the mirror, and check access with a plain SQL query.

Test keys for test payments.

Test API keys work only in a test project, and a test project takes only Stripe test keys. Test payments never touch live access.

JSON over HTTPS

Bearer API keys. Test keys start with qk_test_ and never touch live data.

Twice is safe

A purchase reported by your app and by the store webhook is applied once.

Signed webhooks

HMAC SHA-256 over the timestamp and the raw body, retried with backoff.

Outages never lock users out

The TypeScript SDK answers with the last known access for up to an hour.
