Developers

The check before the bank, as an API.

For AP platforms, payroll providers and finance teams that build their own payment flow. Send a run, get every payment back clear or held, and release a clean file. One OpenAPI document describes all of it.

Quickstart See the code

Five steps around the file you already make.

  1. Send the run before the bank

    POST the NACHA file, a CSV, or the payments as JSON. Every payment comes back clear or held, with its findings.

  2. Show held payments to a person

    Each finding has a code for your logic and a message for the person deciding.

  3. Record the decision

    Approve or reject, with a reason and the reviewer. Two people above the threshold.

  4. Release and send

    The clean file comes back with the totals recomputed. You send it to the bank, as before.

  5. Hear about it

    Signed webhooks when a payment is held, a run is released or a vendor is verified.

For platforms

You send payments for many businesses. Protect all of them at once.

An AP platform or payroll provider sees the same bank accounts across many customers. Quarter gives you the checks and the network behind them, by API.

Account checks

Before your platform pays an account, ask: is the routing number real, has another business confirmed this account, has one reported it? Nothing is stored.

Fraud reports

When one of your customers is defrauded, report the account. Every Quarter customer that pays it is held from then on. Reports made in error can be withdrawn.

Payment run checks

Run the same thirteen checks on the payments your platform sends for each customer, and keep their vendors, history and evidence apart.

Vendor verification links

Ask Quarter for a link and send it from your own product. The vendor confirms through their bank login.

For AI coding tools

Point your AI tool at the contract.

The exact shape of every route is one OpenAPI 3.1 document, served by the API itself without a key. The docs are plain Markdown too.
