Developers

The check before the bank, as an API.

For AP platforms, payroll providers and finance teams that build their own payment flow. Send a run and get every payment back clear or held. People decide and release a clean file in the console. One OpenAPI document describes all of it.

Quickstart See the code

Five steps around the file you already make.

  1. Send the run before the bank

    POST the NACHA file, a CSV, a check register, or the payments as JSON. Every payment comes back clear or held, with its findings.

  2. Show held payments to a person

    Each finding has a code for your logic and a message for the person deciding.

  3. People decide in the console

    A person signed in to Quarter approves or rejects, with a reason. Two different people at or above the threshold. An API key never decides.

  4. Release and send

    A person releases the run in the console and gets the clean file with the totals recomputed, or the Positive Pay file for a check run. You send it to the bank, as before.

  5. Hear about it

    Signed webhooks when a payment is held, a run is released or a vendor is verified.

For platforms

You send payments for many businesses. Check them the same way.

An AP platform or payroll provider can run Quarter's checks for each customer by API, with every customer's vendors and evidence kept apart.

Account checks

Before your platform pays an account, ask: is the routing number real, has another business confirmed this account, has one reported it? Nothing is stored.

Fraud reports

When a business is defrauded, a person signed in to its Quarter console reports the account. Payments to it are then held for other Quarter customers too. Only live projects report, and a report made in error can be withdrawn.

Payment run checks

Run the same twenty-two checks on the payments your platform sends for each customer, and keep their vendors, history and evidence apart.

Vendor verification links

Ask Quarter for a link and send it from your own product. The vendor confirms through their bank login.

For AI coding tools

Point your AI tool at the contract.

The exact shape of every route is one OpenAPI 3.1 document, served by the API itself without a key. The docs are plain Markdown too.

Tell your AI tool

Read GET $QUARTER_API_URL/openapi.json and /llms.txt.
Before our payment file goes to the bank, POST it to
/v1/payment_runs. Show held items with their findings.
People decide and release in the Quarter console; read
the run, or the payment_run.released webhook, for the
result. Test keys start with qk_test_.
